# План: Добавление поддержки PostgreSQL

## Обзор

Добавить поддержку PostgreSQL в Family Tree FastAPI с сохранением обратной совместимости с SQLite. Конфигурация через env vars с префиксом `FAMILY_TREE_`.

---

## Шаг 1: Добавить `psycopg2-binary` в `pyproject.toml`

**Файл:** `pyproject.toml`

Добавить в `dependencies`:
```toml
"psycopg2-binary>=2.9.0",
```

---

## Шаг 2: Расширить `Settings` в `config.py`

**Файл:** `src/familytree/core/config.py`

Добавить поля DB-конфигурации:
- `db_url: str | None = None` — полный URL (наивысший приоритет)
- `db_host: str = "127.0.0.1"`, `db_port: int = 5432`, `db_name: str = "familytree"`, `db_user: str = "familytree"`, `db_password: str = ""`
- `@property use_postgresql` — определяет, используется ли PostgreSQL
- `@property resolved_db_url` — возвращает итоговый URL (PostgreSQL или SQLite fallback)

Приоритет: `FAMILY_TREE_DB_URL` > индивидуальные параметры > SQLite fallback.

---

## Шаг 3: Рефакторинг `database.py`

**Файл:** `src/familytree/core/database.py`

Основные изменения:
1. Lazy-import `settings` из `config.py` (через `_get_settings()` для избежания circular imports)
2. Создание engine на основе `settings.resolved_db_url`
3. Сохранение логики SQLite inline-миграций (обёрнута проверкой `engine.dialect.name == 'sqlite'`)
4. `init_db()` работает для обоих бэкендов:
   - SQLite: `create_all()` + inline migrations
   - PostgreSQL: только `create_all()` (миграции через Alembic)

**Важно:** `Base`, `SessionLocal`, `engine` остаются экспортированными — `deps.py`, `models.py`, `main.py` не требуют изменений.

---

## Шаг 4: Настройка Alembic

### `alembic.ini`
Заменить `sqlalchemy.url = driver://user:pass@localhost/dbname` на закомментированную строку — URL резолвится динамически из env vars.

### `alembic/env.py`
Полная переписывание файла:
- Импорт `Base` из `familytree.core.database`
- Чтение тех же env vars, что и `config.py`
- `target_metadata = Base.metadata` для `--autogenerate`
- Реализация `run_migrations_offline()` и `run_migrations_online()`

---

## Шаг 5: Генерация начальной миграции

После шагов 1-4 выполнить:
```bash
alembic revision --autogenerate -m "initial schema"
```

Создаст `alembic/versions/___initial_schema.py` с таблицами: persons, relationships, phones, addresses, name_variants.

---

## Шаг 6: Обновить `main.py` — lifespan для инициализации БД

**Файл:** `src/familytree/main.py`

Заменить `app = FastAPI(...)` на lifespan-контекст:
```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    init_db()
    yield
```

`init_db()` уже обрабатывает оба бэкенда (шаг 3), поэтому код не меняется.

---

## Шаг 7: Создать `.env.example`

**Файл:** `.env.example` (новый)

Документация по всем переменным окружения:
```bash
FAMILY_TREE_DB_URL=postgresql+psycopg2://user:pass@localhost:5432/familytree
FAMILY_TREE_DB_HOST=127.0.0.1
FAMILY_TREE_DB_PORT=5432
FAMILY_TREE_DB_NAME=familytree
FAMILY_TREE_DB_USER=familytree
FAMILY_TREE_DB_PASSWORD=
FAMILY_TREE_DEBUG_SQL=true
```

---

## Верификация

1. **SQLite режим (по умолчанию):** Запустить без DB env vars — должно работать как раньше
2. **PostgreSQL режим:** Установить `FAMILY_TREE_DB_URL`, запустить `alembic upgrade head`, запустить приложение
3. **Alembic autogenerate:** `alembic check` — должен показать "No changes detected"
4. **Тесты:** `pytest tests/`
