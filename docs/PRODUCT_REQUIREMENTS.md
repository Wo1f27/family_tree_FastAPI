# Продуктовые требования — Система генеалогического древа

## 1. Описание продукта

**Family Tree** — система для создания, хранения и визуализации генеалогических древ. Позволяет пользователям вести персональные семейные архивы, устанавливать родственные связи, импортировать/экспортировать данные и делиться результатами.

**Целевая аудитория:**
- Люди, интересующиеся своей родословной
- Семьи, ведущие совместный архив
- Генеалоги-исследователи
- Образовательные учреждения (исторические проекты)

## 4. MVP — Минимально жизнеспособный продукт

### 4.1 Функциональные требования MVP

#### 4.1.1 Модуль Auth

| ID | Требование | Приоритет | Критерии приёмки |
|----|-----------|-----------|-------------------|
| AUTH-01 | Регистрация пользователя (username, email, пароль) | Высокий | Пользователь может создать аккаунт |
| AUTH-02 | Вход по username/email + пароль | Высокий | Пользователь получает JWT-токен |
| AUTH-03 | Выход из системы | Высокий | Токен инвалидируется |
| AUTH-04 | Восстановление пароля через email | Средний | Письмо с токеном сброса |
| AUTH-05 | Хеширование паролей (bcrypt) | Высокий | Пароль не хранится в открытом виде |
| AUTH-06 | JWT-токены (access + refresh) | Высокий | Access 15 мин, refresh 7 дней |

#### 4.1.2 Модуль User Management

| ID | Требование | Приоритет | Критерии приёмки |
|----|-----------|-----------|-------------------|
| USER-01 | Просмотр профиля | Высокий | Отображается username, email, дата регистрации |
| USER-02 | Обновление email | Высокий | Email уникален, валидирован |
| USER-03 | Смена пароля | Высокий | Требуется текущий пароль |
| USER-04 | Username неизменяемый | Высокий | Нельзя изменить после регистрации |
| USER-05 | Деактивация аккаунта (admin) | Средний | Админ может деактивировать |

#### 4.1.3 Модуль Person CRUD

| ID | Требование | Приоритет | Критерии приёмки |
|----|-----------|-----------|-------------------|
| PERS-01 | Создание карточки персоны | Высокий | Имя и фамилия обязательны |
| PERS-02 | Просмотр карточки персоны | Высокий | Только владелец видит свои карточки |
| PERS-03 | Обновление карточки персоны | Высокий | Частичное обновление (только переданные поля) |
| PERS-04 | Удаление карточки персоны | Высокий | Связи тоже удаляются |
| PERS-05 | Список всех персон пользователя | Высокий | Пагинация (skip/limit) |
| PERS-06 | Поля: имя, фамилия, отчество, даты рождения/смерти, пол, биография | Высокий | Все поля опциональны кроме имени и фамилии |
| PERS-07 | Владение: owner_id привязка к пользователю | Высокий | Пользователь видит только свои карточки |

#### 4.1.4 Модуль Relationship

| ID | Требование | Приоритет | Критерии приёмки |
|----|-----------|-----------|-------------------|
| REL-01 | Создание связи между персонами | Высокий | Обе персоны принадлежат пользователю |
| REL-02 | Типы связей: родитель, ребёнок, супруг, сиблинг, другое | Высокий | Enum RelationshipType |
| REL-03 | Удаление связи | Высокий | Связь удаляется, персоны остаются |
| REL-04 | Получение всех связей персоны | Высокий | Возвращает список связей |
| REL-05 | Получение связей по типу | Высокий | Фильтрация по RelationshipType |
| REL-06 | Валидация: персона не может быть родственником себе | Высокий | Ошибка при person_1 == person_2 |
| REL-07 | Валидация: дублирующиеся связи запрещены | Средний | Одна пара персон — одна связь одного типа |

| ID | Требование | Приоритет | Критерии приёмки |
|----|-----------|-----------|-------------------|

| TREE-02 | Навигация: зум, перемещение | Высокий | Мышь/тач для управления |
| TREE-03 | Клик по узлу → карточка персоны | Высокий | Модальное окно или панель |

## 11. Риски и митигация

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Сложность визуализации дерева | Средняя | Высокое | Использовать готовые библиотеки (D3.js, vis.js) |
| Дубликаты персон при совместной работе | Высокая | Среднее | Проверка по имени + датам при создании |
| Производительность при больших деревьях | Средняя | Высокое | Ленивая загрузка, пагинация, PostgreSQL |
| Потеря данных | Низкая | Критическое | Бэкапы БД, GEDCOM-экспорт |
| Безопасность данных | Средняя | Критическое | JWT, bcrypt, изоляция данных, HTTPS |

## 12. Критерии готовности MVP

- [ ] Пользователь может зарегистрироваться и войти
- [ ] Пользователь может создавать/редактировать/удалять карточки персон
- [ ] Пользователь может устанавливать родственные связи
- [ ] Пользователь может визуализировать своё дерево
- [ ] Данные изолированы между пользователями
- [ ] Пароли хешируются (bcrypt)
- [ ] API защищён JWT-токенами
- [ ] Unit-тесты покрывают > 70% use cases
- [ ] API задокументирован (OpenAPI/Swagger)
